# 师伴技能地图 · 原子技能与组合契约

> 本文件是「师伴」技能层的**总览地图**，面向人与 AI。
> 核心定调：**所有课型/任务类型都不是硬编码实体，而是「原子技能 + 工具」的默认组合方案。**
> 系统内置几种常见类型的默认组合 → 通过与教师对话确认、微调 → 得到本次实际组织。

---

## 一、原子技能（可被任意组装）

每个技能都是一个**可独立调用的原子**，可串行 / 并行 / 嵌套 / 重复。主 Agent 按教师当下需求现场组合。

| 原子 | 职责 | 独立可用性（无上游时） |
|---|---|---|
| `lesson-plan` | 教学设计（支架/目标/流程），含「说课视角」子模式 | ✅ 可仅凭知识点从零设计 |
| `quiz` | 归因型题与批阅模板 | ✅ 可直接从知识点出题（无需先有教案） |
| `class-eval` | 课后评价，双模式：真实课堂 / 微格内省 | ✅ 微格模式无需课堂与学生数据 |
| `class-profile` | 学情查询 / 更新（画像矩阵） | ✅ 可只查不更；无数据即声明 |
| `teacher-growth` | 教师成长报告（培养主线） | ✅ 可从零散观测/内省合成 |
| `html-material` | 教师外部素材库：查询、积累、复用、隔离编排与离线文件交付 | ✅ 可独立查库、复用或从知识点新建 |

---

## 二、组合契约（每个技能必须声明三件事）

> 这是「模块化」的真正完成——技能不只是"能独立跑"，还要**显式声明契约**，主 Agent 才知道怎么拼。

1. **输入契约**：需要什么？（标注 `必须` / `可选` / `缺失时如何降级`）
2. **产出契约**：给出什么？（结构化产物 + 落盘路径）
3. **独立可用性**：没有上游产物时，能否从零服务？能降级到什么程度？

**硬规则**：缺输入时——**问一句** 或 **按最低可用模式服务并显式声明边界**，**绝不编造证据**。

---

## 三、常见类型的默认组合（命名锚点，非封闭枚举）

> 类型只是"默认组合的起点"，可被拆开单用、两两拼接、并行、中途改造。

| 类型 | 默认组合（原子序列） | 常见微调点 |
|---|---|---|
| 新授课 | `class-profile(读)` → `lesson-plan(支架)` → `quiz(理解检验)` → `class-eval(课堂)` → `class-profile(写)` | 跳过学情？只要教案？ |
| 复习课 | `class-profile(掌握诊断)` → `quiz(分层归因)` → `class-eval(薄弱定位)` | 只出题？先诊断？ |
| 微格试课 | `class-eval(微格·内省)` → `teacher-growth(技能点)` | 有录像/同伴观察吗？ |
| 说课 | `lesson-plan(说课视角)` → (可选)`设计评估` | 要稿还是要评？ |

**组合可被**：拆开单用 / 拼接（新授+复习） / 并行（说课∥微格） / 重规划（中途换）。锚点不是课型枚举，用户可自由命名组合。

## 四、任务的「组织图」（task_plan.json）

当本次任务涉及**多轨 / 分段 / 跨会话续接**时，主 Agent 把组装结果落盘为
`data/shiban/task_plan.json`——让"组织形式"可见、可改、可续。

```json
{
  "task_id": "…",
  "goal": "教师本次的真实目标（一句话）",
  "status": "进行中",
  "tracks": [
    { "name": "轨A·说课", "atoms": ["lesson-plan(说课视角)"], "status": "pending", "outputs": ["说课稿"] }
  ],
  "composition": "parallel | sequential | mixed",
  "inputs_available": { "class_profile": false, "current_lesson": true, "students": false },
  "notes": "微调记录 / 用户跳过 / 中途变更"
}
```

## 五、技能间产物流转（可选上下文，非硬接力）

旧版把 `current_lesson.json → current_quiz.json → last_eval.json` 当**硬接力**，导致"没走完上一步就拒绝服务"。

**新版**：这些文件是**可选上下文**——

- 有 → 读来对齐（如 `quiz` 读 `current_lesson.json` 让题目绑定支架）
- 无 → **不阻塞**，从对话 / 教师提供处获取，或按最低可用模式服务

| 中间产物 | 谁写 | 谁可选读 |
|---|---|---|
| `current_lesson.json` | 主 Agent 选定候选后 | `quiz` / `class-eval` |
| `current_quiz.json` | `quiz` | `class-eval` |
| `last_eval.json` | `class-eval` | `class-profile` / `teacher-growth` |
| `last_microeval.json` | `class-eval(微格模式)` | `teacher-growth` |
| `teacher_growth_report.json` | `teacher-growth` | 教师确认后归档为 L2 索引 |
| `teacher_profile.json` | 主 Agent（偏好持久化） | 全部 |

### teacher_profile.json 结构（含观察记录）

`preferences` 是指令性偏好，主 Agent 必须遵守；`observations` 是非指令性的交互画像记录，仅作背景参考、**不得当作偏好执行**。两者区分，避免把一句观察误升级为长期规则。

```json
{
  "preferences": [{"key": "", "value": "", "source_turn": 0, "recorded_at": "ISO"}],
  "observations": [{"key": "", "value": "", "source_turn": 0, "recorded_at": "ISO", "note": "为何不写入 preferences"}],
  "schema": "结构说明"
}
```

本文件属 L1 层个人数据，默认不纳入版本控制。

### 微格产物的扩展字段

`last_microeval.json` 在技能核心 schema 之外可携带 `scaffold_candidates_for_next_lesson` 等向前衔接字段：它把本次内省结论导向下一次 `lesson-plan`，属允许的扩展。扩展字段必须与核心字段语义一致，不得覆盖或改写 `model_view`、`teacher_view`、`divergence` 的原始内容。

## 六、数据生命周期约定（L0/L1/L2）

工作区运行数据按内容层级管理，不改变现有画像库或跨会话持久服务：

- **L0 原始材料**：课堂记录、微格转写、教师笔记、同伴观察等尽量完整保存到 `data/shiban/raw/`。原始来源只追加、不由 AI 改写或压缩；更正应另存新版本并保留关系。
- **L1 进行中工作**：当前教案、随堂测、单次评价、微格评价、`task_plan.json` 等保留详版，在 `meta.status` 标记 `进行中` 或 `已归档`。路径保持稳定，不因状态变化移动主文件。
- **L2 历史连接**：归档时新增轻量索引（`*.index.json`），包含任务/事件标识、时间、主题、状态、L0/L1 引用、关键结论、趋势标签和数据缺口，不复制原始材料或整份详版。

归档是“新增 L2 索引 + 更新状态”，不是删除/覆盖 L0 或 L1。查询与成长报告默认读 L2；有明确问题再按引用回溯。AI 可建议或执行归档整理，但不得声称已保存到不存在的存储服务；本轮 `services/*.py` 与数据库持久化机制保持不变。详细规则见 `构建/数据生命周期与任务状态_v1.md`。

## 七、培养主线（贯穿）

「强化对教师的培养」不是独立流程，而是**可被任意组合挂载的视角**：

- `class-eval` 各模式都产出可直接喂给 `teacher-growth` 的证据；
- `teacher-growth` 把零散证据沿时间轴合成为**教师成长报告**（能力趋势 + 一个可练点）。
- 原则：培养是**陪练/镜子**，不是**考官**——只呈现可改进的行为，不贴人格标签，自我评价权归教师。
