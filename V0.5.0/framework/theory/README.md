# 理论库（theory）

应答一个前置问题：**师伴凭什么这样建议？**

## 与语料的区别

| | 语料（corpus） | 理论库（theory） |
|---|---|---|
| 内容 | 教材、课标原文 | 论文、专著、标准 |
| 作用 | 说"教什么" | 说"为什么这样教" |
| 归属 | 教师导入（版权） | **随包**（可公开引用） |
| 引用 | 页码可核验 | 文献 + 页码 + 原文 |

两者都带页码，但**语料是燃料，理论库是尺子**。

## 三层结构

```
framework/theory/
├── builtin/        ← 随包内置，版本化，只读
│   ├── manifest.json
│   ├── literature/   论文与专著（md，带 <!-- p.N --> 页码标记）
│   ├── standards/    国家/考试标准（规定"应该达到什么"）
│   └── digests/      提炼后的框架（工具真正要读的）
├── derived/        ← 使用中补充，教师个人，不随包更新
└── README.md
```

## 内置 vs 补充：为什么必须分开

| | builtin | derived |
|---|---|---|
| 谁写的 | 项目维护者 | 教师自己 |
| 随包更新 | ✅ 覆盖 | ❌ 永不覆盖 |
| 可导出分享 | ✅ | 由教师决定 |
| 引用编号 | 稳定 `T-BUILTIN-nnn` | `T-DERIVED-nnn` |
| 冲突时 | 以 derived 为准（教师看法优先） | — |

**理由**：教师补充的文献不能因为升级插件就消失，也不能被内置文献的权威性压制。
系统提示里内置的是"参考"，教师补充的是"他的依据"。

## 引用格式

任何建议若要主张理论依据，必须能写成：

```
〔理论依据：张春雷 2024《生物学核心素养…》p.3｜builtin｜quote:"程度分级与情境创设需对应"〕
```

- `source`：`builtin` 或 `derived`
- `page`：原 PDF 页序（与文献里的 `<!-- p.N -->` 一致）
- `quote`：≤40 字原文，**必须能在该页复现**

## 与 corpus 的关系

理论库不进 `corpus.db`，也不参与教材检索。
它通过 `theory` 字段进入产物：

```jsonc
"cites_theory": [
  {"id":"T-BUILTIN-003","source":"builtin","page":3,
   "quote":"…","supports":"S3.difficulty_causes"}
]
```

`lesson validate` 会检查 `page` 存在、`quote` 可复现（与语料引用同一套机制）。
