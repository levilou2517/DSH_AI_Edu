# 师伴 v0.4.0 规模与版本基线

**目标版本：** v0.4.0（技能原子组合与数据生命周期约定）  
**状态：** 实施中  
**范围基线：** A 域 `DSH_AI_Edu`；B 域用户自建 `shiban` preset。

## 1. 目标

在现有四项专业技能和真实闭环资产基础上完成原子契约与主 Agent 组合语法：各技能可独立、串行、并行、嵌套或重规划；缺少上游输入时降级并说明，不将默认组合固化为封闭课型。新增微格内省双线评价与跨次教师成长合成，并引入 L0/L1/L2 生命周期及任务状态约定。

## 2. 架构边界

- A 域：`.dsh/skills/`、`data/shiban/task_plan.json`、版本与 schema 文档。
- B 域：`~/.dsh/.agent-presets/shiban/agent.cordis.yml` 与 `preset.yml`，由该用户自建 preset 独立版本管理。
- DSH Host：Skills、文件沙箱、Agent/Subagent 注册表与跨会话能力仍由宿主提供；不得将宿主共享 Service 移入单会话 preset。
- 本轮不修改 `services/*.py`、数据库 schema、Windows 脚本和持久化服务。现有画像 SQLite、原始课堂素材与跨会话数据服务继续按原机制运行。

## 3. v0.4.0 交付物

- 原子技能：`lesson-plan`、`quiz`、`class-profile`、双模式 `class-eval`、独立 `teacher-growth`。
- 组合地图：命名方案只是可拆/可拼/可并行/可重规划的默认锚点；示例为新授课、复习课、微格试课、说课，非穷举。
- 任务组织图：仅多轨、分段、跨会话续接时使用 `task_plan.json`，包含顶层和轨道状态。
- 数据约定：L0 原始材料尽可能完整保留；L1 详版路径稳定并显式状态；L2 索引轻量引用 L0/L1。归档新增 L2，不覆盖原材料或详版。
- 报告 schema v2：包含 model_view、teacher_view、必需 divergence 与成长练习点。
- 版本文档：本文件及 A/B 两域 v0.4.0 基线记录。

## 4. 验收标准

1. 五个技能均声明输入、产出、独立使用边界；缺失输入不阻塞、不编造。
2. 可由主 Agent 按用户目标单用或组合技能；复合示例覆盖“新授+复习”拼接和“说课并行微格”。
3. 无学生证据自动走微格模式，结果不含学生达成度推断。
4. 单次评价有 model_view、teacher_view、divergence；微格材料不足时明确证据不足。
5. 成长原子至少两次可比记录才描述趋势，最多给一个优先练习点，教师可确认/修订。
6. 归档保留 L1 与 L0，仅新增 L2 索引；引用核验失败不得报告归档成功。
7. task plan 的任务状态与轨道状态可表达进行中、完成、归档及阻塞。
8. 既有真实课堂四模块链路仍可由现有素材验证；不得因新 schema 改写或删除既有原始样例。

## 5. 版本决策

- 文档拆分：报告 schema 与生命周期规范分开维护。
- L1/L2：同目录、主路径稳定、状态字段显式；归档索引使用 `*.index.json`。
- 生命周期规范：技能 README 简述原则，构建目录保留独立规范全文。
- 微格成长焦点：每次一个；divergence 必需；`last_microeval.json` 为 L1，归档时新增 L2。
- teacher-growth：独立原子，读取 L2 为主并按需回溯详情。
- 默认组合保留四个常见示例，明确非穷举。
- 采用现有草案为基础继续，不执行破坏性回退。

## 6. 非目标与限制

本版本建立行为与数据治理契约，不等同于实现自动归档服务、自动备份、数据库事务或跨工作区数据迁移。凡当前工具或存储层不能保证的操作，Agent 必须如实说明，不得声称已执行。版本标签与提交应在 A 域和 B 域各自仓库独立创建。
