# 师伴系统优化需求说明（v1.0）

本文档将前序讨论收敛为明确需求，用于对齐范围、分工与验收。共 5 条需求，每条包含：要解决的问题、具体要求、验收标准、边界。


## 需求总览

| 编号 | 名称 | 类型 | 优先级 |
|---|---|---|---|
| R1 | 数据存储独立化 | 基础设施 | P0 |
| R2 | 教材知识库接入 | 数据基础 | P0 |
| R3 | 教案生成完整化与组件化 | 核心功能 | P1 |
| R4 | 课堂数据对话式获取 | 核心功能 | P1 |
| R5 | HTML 课程素材生成 | 交付能力 | P2 |

**依赖关系：**

- R3 依赖 R1、R2
- R4 依赖 R1
- R5 依赖 R3

**已明确不做的事：**

- 不做多租户 SaaS，不做用户权限体系
- 不做前端界面，所有交互仍在 DSH Web UI 内
- 不做向量检索，MVP 用 SQLite FTS5
- 不做音频采集与转写，输入仍是结构化文本/对话
- 不做教材的 OCR 全量转换，只转 MVP 所需章节


## R1 数据存储独立化

### 要解决的问题

现有班级数据存储在工作区内的单表 SQLite 中。多班级、多教师、跨学期场景下无法扩展；换工作区或换 preset 访问不到数据；Agent 直接写 SQL 易出错；数据无法跨 Agent 共享。

### 具体要求

**R1.1 存储位置**

数据存储独立于 DSH 工作区，位于用户级目录 `~/.shiban/`。目录结构固定为：

```
~/.shiban/
├── data/          # SQLite 数据库
├── schema/        # 建表语句
├── migrations/    # 迁移脚本
├── bin/           # CLI 工具
├── templates/     # HTML 模板（R5 使用）
└── knowledge/     # 教材 md（R2 使用）
```

**R1.2 数据模型**

必须支持以下实体及其关系：班级、教师、教师-班级关系、课节、课节指标、课堂记录、课后评价、教师画像。

关键约束：
- 班级与教师是多对多关系
- 课节表是中心表，所有分析数据从课节派生
- 课堂记录必须区分“教师亲口说的”（`teacher_said`）和“Agent 推断的”（`agent_inferred`），并记录置信度
- 教师画像使用 JSON 字段，不锁死维度

**R1.3 访问方式**

Agent 不直接写 SQL。所有数据读写通过 CLI 工具 `~/.shiban/bin/shiban-store` 完成。CLI 用 Python 标准库实现，零第三方依赖，输出 JSON 格式。

至少支持以下命令：
- 创建/查询班级
- 创建/查询课节
- 写入/查询课节指标
- 写入/查询课堂记录（含 source 和 confidence）
- 写入/查询课后评价
- 查询“班级 × 支架类型 × 通过率”矩阵

**R1.4 迁移**

现有 `data/shiban/class_profile.db` 中的数据需迁移到新结构。迁移是一次性脚本，执行后旧文件可保留但不再写入。

**R1.5 版本控制边界**

入 Git：schema、迁移脚本、CLI 源码、模板、教材 md、技能定义。
不入 Git：`~/.shiban/data/` 下的数据库文件、venv、`__pycache__`。

### 验收标准

1. 创建两个班级，各自写入 3 节课的数据，互不干扰
2. 切换 DSH 工作区后，通过 CLI 仍能查到同一份数据
3. CLI 能输出指定班级的“支架类型 × 通过率”矩阵
4. `classroom_notes` 表中每条记录都有 `source` 和 `confidence` 字段
5. 数据库文件不在 Git 仓库中

### 边界

不实现：多用户并发写、数据库复制、备份恢复、远程同步。


## R2 教材知识库接入

### 要解决的问题

教案生成依赖 LLM 泛化知识，没有教材和课标依据。教师无法验证建议的出处，也难以判断建议是否符合教学进度。

### 具体要求

**R2.1 数据范围**

MVP 阶段只转换以下内容：
- 《普通高中生物学课程标准（2017年版2020年修订）》全文
- 人教版必修2 第3章（基因的本质）

后续按优先级扩展：必修2 全册 → 选择性必修1 → 选择性必修2、3。

**R2.2 转换流程**

PDF → 结构化文本 → Markdown → 切块 → 入库。

必须保留：章节标题层级、课标编号（如 3.1.3）、教材栏目名（如“本节聚焦”“思考·讨论”）、表格、图注、页码。

必须清洗：页眉页脚、页码标记、水印、版权页、后记。

**R2.3 存储双轨**

Markdown 文件是 source of truth，存放于 `~/.shiban/knowledge/`，入 Git，人类可读、可 diff。

SQLite 索引是 Agent 检索用，存放于 `~/.shiban/data/textbook.db`，不入 Git，含 FTS5 全文索引。

**R2.4 元数据**

每个 Markdown 文件头部必须带 YAML Front Matter，至少包含：
- `id`：唯一标识
- `source_type`：课标 / 教材 / 教参
- `volume`：册次
- `chapter` / `section`：章节
- `knowledge_point`：知识点
- `page_start` / `page_end`：页码
- `academic_quality_level`：学业质量水平（如适用）
- `core_literacy`：核心素养维度（如适用）

**R2.5 检索接口**

CLI 提供 `shiban-store kp search` 命令，支持按知识点、章节、关键词检索。返回内容含原文片段、来源、页码。

**R2.6 与教案生成的对接**

`lesson-plan` 技能在生成教案前必须调用 `kp search` 获取教材原文和课标条目。生成的教案中必须至少引用 2 条课标或教材原文，且引用可追溯。

### 验收标准

1. `shiban-store kp search "DNA复制"` 能返回教材原文和对应课标条目
2. 返回结果包含章节、页码、课标编号
3. 生成的 DNA 复制教案中至少引用 2 条教材或课标原文
4. 引用可追溯到具体章节和页码

### 边界

不转换：选修课程内容、非人教版教材、教参全文、习题集。
不实现：向量检索、跨语言检索、自动摘要。


## R3 教案生成完整化与组件化

### 要解决的问题

现有 lesson-plan 只输出“候选过渡性知识方案 + 推荐理由”，不是教师能直接使用的教案。教师无法只修改某一部分，每次都得重新生成整份。

### 具体要求

**R3.1 教案结构**

生成的教案必须符合以下十大板块结构：
1. 基本信息
2. 课标与知识结构化分析
3. 学情与 ZPD 分析
4. 教学目标（核心素养四维度）
5. 教学重难点与突破策略
6. 核心问题与问题链
7. 学习活动序列
8. 板书/认知地图设计
9. 分层作业
10. 教学反思

**R3.2 组件化**

教案由 9 个原子组件拼装而成，每个组件可独立调用、独立重做：

| 组件 | 输入 | 输出来源 |
|---|---|---|
| 基本信息 | 教师/班级/课题 | 直接填写 |
| 学情分析 | 班级 ID + 知识点 | R1 的班级画像 |
| 教学目标 | 知识点 + 课标 | R2 的课标条目 |
| 重难点 | 知识点 + 班级水平 | 画像 + 课标 |
| 过渡性知识 | 班级画像 + 教材 | R1 画像 + R2 教材 |
| 教学过程 | 教案上下文 | 综合 |
| 板书设计 | 知识点 + 支架 | 综合 |
| 随堂测 | 过渡性知识 | quiz 技能 |
| 分层作业 | 知识点 + 认知层次 | 综合 |

**R3.3 与既有素材库对接**

必须对接用户已提供的教案模板系统：
- `01_通用主模板.md` 是主骨架
- `课型插件 A-E` 决定课型特定内容
- `原子化素材库` 提供可插入的素材卡
- `01_目标动词库.md` 用于教学目标
- `02_核心问题与问题链模板.md` 用于核心问题
- `07_原子卡E_复习课.md` 的 E3/E4 用于作业和反思

**R3.4 存储与追溯**

每次生成的教案写入 `~/.shiban/data/shiban.db` 的 `lessons.plan_snapshot` 字段，同时在 `data/shiban/lessons/{lesson_id}/plan.md` 保留 Markdown 文件。

组件版本、使用的教材 chunk_id、使用的课标条目编号，必须记录在元数据中。

**R3.5 单独重做**

教师可以只让 Agent 重做某个组件（如“重新生成学情分析”），不影响其他板块。

### 验收标准

1. 生成的教案包含全部十大板块
2. 学情分析引用了班级画像数据（如“类比支架通过率 81%”）
3. 教学目标引用了课标编号（如“依据课标 3.1.3”）
4. 过渡性知识引用了教材原文
5. 教师可单独重做任一组件
6. 教案快照与元数据写入数据库

### 边界

不做：一键生成全学期教案、多教师协作编辑、教案在线编辑界面。


## R4 课堂数据对话式获取

### 要解决的问题

现有 class-eval 要求教师提交结构化记录，但教师记不住细节、不愿填表，主观感受无法塞进结构化字段。

### 具体要求

**R4.1 对话四阶段**

Agent 引导教师通过对话完成课后反思，流程固定为四阶段：

| 阶段 | 时长 | 目的 |
|---|---|---|
| 开放唤起 | 约 1 分钟 | 让教师自由描述整体感受 |
| 聚焦追问 | 2-3 分钟 | 指向具体事件，追问 2-3 个方向 |
| 证据校准 | 1-2 分钟 | 摆出 Agent 推断，请教师确认或修正 |
| 自动写入 | Agent 执行 | 提取结构化字段入库 |

**R4.2 提取规则**

从对话中提取结构化字段时，必须区分来源：
- 教师亲口说的 → `source=teacher_said`，`confidence` 0.9-1.0
- Agent 推断的 → `source=agent_inferred`，`confidence` 0.4-0.7

**R4.3 行为约束**

- 教师表达疲惫（“累了”“明天再说”）→ 立即收尾，不做分析
- 教师说“没什么特别的” → 记录为“无异常”，不追问
- 追问只指向具体事件，不指向自我评价
- 单次对话不超过 5 轮
- 每轮 Agent 提问不超过 2 个问题

**R4.4 对话存档**

完整对话存入 `data/shiban/lessons/{lesson_id}/dialog.md`，作为教师专业成长的原始资料。

**R4.5 触发机制**

随堂测批阅完成后自动触发对话邀请，但允许教师延迟或忽略。忽略不影响随堂测数据正常入库。

### 验收标准

1. 教师说“后排玩笔”后，`classroom_notes` 表中有一条 `source=teacher_said` 的记录
2. 教师说“我先去歇会儿”，Agent 简短确认后结束对话
3. Agent 推断的内容标记为 `agent_inferred`，置信度 <0.7
4. 完整对话存档在 `dialog.md`

### 边界

不做：语音输入、自动情绪识别、多教师同时对话、对话内容的自动摘要生成。


## R5 HTML 课程素材生成

### 要解决的问题

教案是 Markdown，教师无法直接投影、打印、分发给学生。需要一层渲染能力，把抽象内容转成可用的 HTML。

### 具体要求

**R5.1 素材类型**

MVP 阶段实现 8 类素材：
- `model`：交互模型图（如 DNA 双螺旋）
- `board`：板书/认知地图
- `quiz`：随堂测互动页
- `experiment`：实验操作单
- `timeline`：科学史时间线
- `table`：证据-推论表/变量表
- `homework`：分层作业页
- `reflection`：课后反思单

MVP 优先实现前 4 类。

**R5.2 输出规范**

生成的 HTML 必须满足：
- 单文件自包含，无 CDN、无外部依赖
- 双击可打开，断网可用
- 含 `@media print` 样式
- 兼容移动端（viewport meta + 响应式）
- 中文字体使用系统字体栈
- 图片用 SVG 内联或 base64
- 无未替换的占位符

**R5.3 模板驱动**

LLM 只负责填充模板占位符，不写 HTML 样式。模板库位于 `~/.shiban/templates/html/`，与数据分离。

**R5.4 新增 subagent**

在 preset 中新增 `html-material` subagent，技能定义位于 `skills/html-material.md`。主 Agent 识别“生成课件素材”“做成 HTML”“投影用的图”“打印实验单”等意图时，委派该 subagent。

**R5.5 输出位置**

素材写入 `data/shiban/lessons/{lesson_id}/materials/`，每个素材含 HTML 文件和 meta.json 元数据。

**R5.6 更新策略**

meta.json 记录 `source_hash`（来源片段哈希）。教案更新后，Agent 检测 hash 变化，提示教师“教案已更新，是否重新生成素材？”，由教师决定，不强制覆盖。

**R5.7 自动校验**

生成后必须通过 `validate_html.py` 校验：无未替换占位符、无外部依赖、含打印样式、含 viewport、文件大小合理。

### 验收标准

1. 生成的 HTML 双击可打开，无外部依赖
2. `@media print` 样式生效，打印不丢内容
3. 移动端显示正常
4. 校验脚本通过
5. 教师说“把 DNA 双螺旋做成投影用的图”，Agent 正确识别为 `model` 类型并生成
6. 教案更新后，Agent 提示是否重新生成

### 边界

不做：在线编辑 HTML、模板可视化编辑器、素材版本回滚、多素材打包成页面。


## 实施优先级与顺序

**第一阶段（P0，基础设施）**
- R1 数据存储独立化
- R2 教材知识库接入（课标 + 必修2第3章）

**第二阶段（P1，核心功能）**
- R4 课堂数据对话式获取（改造 class-eval）
- R3 教案生成完整化与组件化（先做 3 个核心组件：学情分析、教学目标、过渡性知识）

**第三阶段（P2，交付能力）**
- R3 剩余组件（教学过程、板书、作业）
- R5 HTML 课程素材生成（先做 model、board、quiz、experiment 四类）

**第四阶段（P3，完善）**
- R5 剩余四类素材
- 教师画像跨学期累积
- 教材数据扩展到必修2全册
