# 师伴系统版本控制机制（定稿）

**状态：** 已落地基线
**日期：** 2026-09-22
**目的：** 保证任何改动均可回退。本文档是 `.gitignore` 与 A/B 两域仓库管理的依据。

---

## 一、两域分离

师伴系统横跨两个 Repository 域，回退机制各自成立：

| 域 | 仓库 | 位置 | 管什么 | 基线标签 |
|---|---|---|---|---|
| A 域 | `DSH_AI_Edu` | 工作区现有 git | 教材 md / `材料`模板 / `构建`文档 / `scripts` / `.dsh`skills | `v0.1.0` |
| B 域 | `dsh-shiban-presets` | `~/.dsh/.agent-presets/` 新建独立 git | 运行预设 `agent.cordis.yml` + `preset.yml` | `shiban-v0.1.0` |

> 关键：B 域（真正产生行为的预设代码）比 A 域更脆弱，必须独立成库。

## 二、决策记录

| # | 决策 | 结论 |
|---|---|---|
| 1 | 数据是否纳入版本控制 | **不纳入**。`~/.shiban/data/` 用「schema/seed 脚本幂等重建 + 定期备份」管理，与代码解耦。 |
| 2 | 是否需要远端 | **要，GitHub**。连通性实测通过（HTTPS 通 / SSH 不通，走 HTTPS+token）。 |
| 3 | tar 包去留 | **不入 git**。为分享/发布临时产物，已拆解进 A/B 两库。 |
| 4 | 技能归属 | **归 A 域**（工作区），随项目走。 |

## 三、回退保证组合

```
代码（A+B）→ git tag + revert，随时回到 v0.1.0 基线
数据       → 迁移脚本 + 备份，独立于代码
每次改动   → 原子 commit，可单独撤销某一环
```

## 四、GitHub 接入（实测记录）

- **认证**：HTTPS + Personal Access Token（fine-grained）。用户名 = GitHub 账户名，token 当密码。
- **已验通**：push / pull / clone 往返正常（token 具备 `Contents: read/write`）。
- **不通**：SSH 22 端口被环境阻断；gh CLI 二进制 CDN（`release-assets.githubusercontent.com`）超时 → 不用 gh，用 git 原生 HTTPS。
- **凭据安全**：token 经一次性 credential helper（环境变量）注入，不落盘、不进历史、不进 remote URL。

## 六、v0.4.0 基线增补

v0.4.0 继续遵守 A/B 双域独立版本管理，不以工作区 A 域提交代替 B 域 preset 版本记录：

| 域 | v0.4.0 内容 | 基线记录要求 |
|---|---|---|
| A 域 | `.dsh/skills/` 原子契约、`data/shiban/task_plan.json` 样例、schema/生命周期/验收文档 | 在 `DSH_AI_Edu` 仓库单独提交并标记 `v0.4.0` |
| B 域 | `shiban/agent.cordis.yml` 编排规则、`preset.yml` 描述 | 在用户自建 preset 仓库单独提交并标记 `shiban-v0.4.0` |
| 数据 | L0 原文、L1 工作详版、L2 轻量索引 | 不因版本基线自动纳入 git；按数据备份与存储政策另行管理 |

本次改动不自动创建提交、tag 或远端 push。完成验收后由维护者核对 A/B 两域实际改动，再分别建立基线；B 域路径以 preset roster 返回的真实路径为准，不修改部署 shipped preset。

## 七、回退操作速查

```bash
# 撤销最近一次改动
git revert HEAD
# 回到之前某提交
git checkout <hash> -- <文件>
# 完全回到基线（丢弃之后所有）
git reset --hard v0.1.0
# 列出版本
git tag ; git log --oneline
```
